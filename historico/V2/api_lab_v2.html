Da descoberta à produção.

O catálogo é uma semente de registry, não um conjunto de conectores implementados. A revisão documental registra o que foi localizado em fontes primárias; condições incompletas ficam explícitas como candidatas ou referências pendentes. Uma falha do leitor web não prova que a API esteja indisponível para clientes reais.

Fluxo proposto: descoberta → documentação → teste técnico → revisão de uso → piloto → produção. Registrar cobertura, origem, data e transformação dos dados; medir disponibilidade em janela representativa antes de depender da fonte.

Arquitetura sugerida: registry → adaptadores de provedor → ingestão e normalização → cache/banco de leitura → capacidades → produtos. Preserve o Core e não exponha um proxy aberto de URLs externas.

Condições: A não garante gratuidade comercial. B exige ETL. C fica fora do requisito estrito zero-cadastro. V exige pesquisa antes de implementação. Prioridades P0/P1/P2 são propostas editoriais.
